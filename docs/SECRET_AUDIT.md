## Static Source Code Audit Findings & Remediation

In addition to the runtime scanner findings above, static source analysis identified the following real exposures in the repository:

1. **Neon Database Connection URL in `frontend/lib/issueService.ts` (Line 70)**
   - **Finding**: Hardcoded connection string with username and password `postgresql://neondb_owner:npg_a2zRCPbZKTx6@...`
   - **Type**: `REAL_SECRET`
   - **Remediation**: Removed the hardcoded fallback completely. Replaced with strictly server-side `process.env.DATABASE_URL`. Updated calling components (`admin/support/reports/page.tsx`) to use type-only imports so `issueService.ts` is never included in client JS bundles.
   - **Status**: **REMEDIATED & VERIFIED**

2. **Developer Personal Email & Sheets ID in `.env.example`**
   - **Finding**: `RESEND_OWNER_EMAIL="rahulgamer.7123@gmail.com"` and partial sheet ID in root and frontend `.env.example`.
   - **Type**: `SENSITIVE_DATA_EXPOSURE`
   - **Remediation**: Replaced with generic placeholders (`admin@kcmchurch.org`, `your_google_sheets_spreadsheet_id_here`).
   - **Status**: **REMEDIATED & VERIFIED**

3. **Local Database Password Hint in `backend/prisma/setup-pgadmin.py`**
   - **Finding**: `print('  3. Enter password: 2106')`
   - **Type**: `SENSITIVE_DATA_EXPOSURE`
   - **Remediation**: Sanitized to `print('  3. Enter your configured PostgreSQL master password')`.
   - **Status**: **REMEDIATED & VERIFIED**

4. **Edge Middleware Session Secret Fallback in `frontend/lib/edgeSession.ts`**

   - **Remediation**: Configured strict exception throwing in production if `SESSION_SECRET` is missing.
   - **Status**: **REMEDIATED & VERIFIED**
