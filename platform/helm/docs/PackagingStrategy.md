# Helm Packaging Strategy - Kingdom of Christ Ministries (KCM Church)

## 1. Overview & Strategy Objectives
This document establishes the official enterprise packaging strategy for Helm charts across all Kingdom of Christ Ministries (KCM Church) Kubernetes services.

The objectives are:
- **OCI-First Distribution**: All charts are stored and distributed as OCI v1 artifacts via `ghcr.io/bunnyvalluri/church-/charts/<chart-name>`.
- **Strict Semantic Versioning**: Charts enforce SemVer 2.0.0 (`MAJOR.MINOR.PATCH`).
- **Modular Subchart Architecture**: Application charts consume platform subcharts via explicit dependency definitions.
- **Immutable Provenance & Signing**: Releases are cryptographically signed using Cosign and GPG keys.

## 3. Chart Standardization Rules

1. **`Chart.yaml` Versioning**:
   - `apiVersion`: `v2`
   - `name`: Matches directory name exactly (lowercase alphanumeric with hyphens).
   - `version`: Chart release version (bumped on chart manifest/value changes).
   - `appVersion`: Application image tag (bumped when application binary/image changes).

2. **Template Hygiene**:
   - Every template must include standard labels generated by `_helpers.tpl` (`helm.sh/chart`, `app.kubernetes.io/name`, `app.kubernetes.io/instance`, `app.kubernetes.io/version`, `app.kubernetes.io/managed-by: Helm`).
   - Resource requests and limits MUST be defined in `values.yaml` and NEVER hardcoded in templates.
   - Probes (liveness, readiness, startup) MUST be configurable via `values.yaml`.

3. **Multi-Environment Configuration**:
   - Default `values.yaml` contains sane production defaults.
   - `values-production.yaml` enables high-availability (HA, replica count >= 3, PDB, pod anti-affinity, high CPU/Memory allocations).
   - `values-staging.yaml` configures staging endpoints and 2-replica setup.
   - `values-development.yaml` enables single-replica low-resource footprint.
